# Contributing to iAUMO

Thank you for helping shape the project responsibly.

## Before contributing

1. Read the relevant RFC and existing discussion.
2. Do not post personal, confidential, precise-location, medical, immigration, legal, or other sensitive information.
3. For a substantial change, open an issue before investing significant work.
4. Keep one focused change per pull request and explain who benefits, risks, alternatives, and validation.

## RFC process

New initiatives and material decisions use numbered RFCs in `docs/rfcs/`.

1. Copy `docs/rfcs/0000-template.md` to the next available number.
2. Open a draft pull request.
3. Identify affected communities and required expert reviewers.
4. Allow a review period appropriate to the stakes; two weeks is a minimum default.
5. Record objections and revise the proposal.
6. The maintainer records Accepted, Rejected, Withdrawn, or Superseded status and the rationale.

Implementation requires its own accepted RFC when safety, data, governance, or real-world operations are involved.

## Pull requests

- Use a branch named `proposal/<topic>`, `docs/<topic>`, or `feature/<topic>`.
- Add tests or validation appropriate to the change.
- Update documentation and disclose third-party material and licenses.
- By contributing, you agree that your contribution is licensed under the repository license unless clearly stated otherwise.

## Conduct and security

Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Report security issues through the process in [SECURITY.md](SECURITY.md), not a public issue.
